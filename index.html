How it works

One handoff. The agent orchestrates; it never holds the credential.

01

The tool mints a link

Your MCP tool reports what the action requires — no phone in the loop.

02

The user proves it

One browser/wallet session: WebAuthn passkey or an OpenID4VP presentation.

03

The action completes

The agent polls, then proceeds — enforced server-side, not a hidden button.

Quickstart

Mount it on any app in ten lines.

import { createStorefront } from "@openmobilehub/credentagent-storefront/server"; import { CredentAgent, age, membership, payment, required, optional } from "@openmobilehub/credentagent-gate"; const store = createStorefront(); const credentagent = new CredentAgent(); credentagent.mount(store.app); // wires the /credentagent/* wallet rails store.gate((order) => credentagent.requirements(order, [ required(age.over(21)), optional(membership.discount(10)), required(payment.in("usd")), ]));
What's newv0.4.0

Beyond the storefront: your checkout, your server, and an agent that shops while you're away.

The gate no longer needs the bundled storefront. Drive a checkout from any Express app, wire it into your own MCP server, let a human approve a spending limit once, and tell other services when an order settles.

A checkout without a storefront. orders.serve(app) wires the whole human-present checkout onto your app; orders.create() mints an approve link per purchase. Amount and age threshold are re-derived server-side — never trusted from the link.

const credentagent = new CredentAgent({ walletOrigin: "https://shop.example" }); // once, at startup credentagent.orders.serve(app); // wire the whole checkout onto your app credentagent.on("order.settled", ({ id }) => fulfill(id)); // per purchase — hand approveUrl to the human const { id, approveUrl } = await credentagent.orders.create({ order, policy: [required(age.over(21)), required(payment.in("usd"))], });

Approve once, the agent spends while you're away. The human approves a bounded budget — how much, per purchase, and what — and the agent buys against it unattended, every rule re-checked server-side on every spend. Age is non-delegable: a 21+ item always steps up to a live human.

credentagent.grants.serve(app); // serves each grant's approve / deny page const grant = await credentagent.grants.create({ merchant: "utopia", budget: 100, perSpend: 30, allow: { categories: ["Beverages"] }, // bound WHAT may be bought, not just how much }); sendToUser(grant.approveUrl); // the human approves ONCE // later, human away const g = await credentagent.grants.retrieve(grant.id); const s = await g.spend({ idempotencyKey: "order-1", items: [{ sku: "coffee" }] }); // → { ok: true, amount: 18, remaining: 82 } or { ok: false, code: "budget-exceeded" | "step-up" | … } await g.revoke(); // kill-switch — the very next spend refuses

Bring your own host. Already have an Express + MCP server, a catalog, and an order store? defineHost() takes those three things and builds the rest — one completion choke point your own tools call, fail-closed on an incomplete setup.

const host = defineHost({ catalog: { createOrder: (items, id) => priceFromMyCatalog(items, id) }, // amount source of truth orderStore: { read: (id) => myOrders.get(id) ?? null }, records: { read: (id) => myCompleted.get(id), write: (rec) => myCompleted.set(rec.orderId, rec) }, signingKey: process.env.GATE_SECRET, }); host.publish(app); // publish the seams onto your app new CredentAgent({ walletOrigin }).mount(app); // serve the proof pages over them // your own place-order tool calls host.complete(…) → { completed, reason? }

Tell a different service when an order settles. A signed order.settled POST — HMAC-SHA256, replay-protected, retried at-least-once — verified on the other side with the familiar constructEvent idiom.

// sending — configure once new CredentAgent({ webhooks: { endpoints: [{ url: "https://fulfillment.example/hooks", secret: process.env.WHSEC }] } }); // receiving — a different service; verify the RAW body const event = constructEvent(req.body, req.get("CredentAgent-Signature"), process.env.WHSEC); if (event.type === "order.settled") fulfill(event.data.object.orderId); // dedupe on event.id

Your brand on the consent pages

new CredentAgent({ branding }) — wordmark, accent, logo. It restyles the chrome only; the honesty footer can't be removed.

Payment credentials on iPhone

The gate presents a stable reader identity on the ISO-mdoc path, which iOS wallets require to show a consistent requester.

Gate any credential

Age, membership, a prescription, payment — all just credentials in one policy.

The built-ins are pre-defined credentials. defineCredential() gates any consequential action with any credential — identity leads, payment settles last.

The wire crypto is real; the issuer trust anchor is not yet — a self-crafted credential would still pass. A presence-only gate is never sold as a real safety control. Branding can restyle the consent pages, but never the honesty footer.
