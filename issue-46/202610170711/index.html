#46 Add a skip-to-content link and a main landmark

ready for human review

index.html has no <main> landmark and no skip link; <body> opens straight into <nav>. Wrap everything between </nav> (line ~598) and <footer> (line ~1030) in one <main id="main">, and add a "Skip to content" link (href="#main") as the first focusable element in <body>, before <nav>. The link is visually hidden until focused, then shown using existing colour tokens only. Add a test in tests/. Nothing else changes.

What changed

I added a "Skip to content" link and a `<main id="main">` landmark to `index.html`. Before this, keyboard and screen-reader users had to tab through the whole sticky nav to reach the content, and the page had no main landmark to jump to. - **Skip link:** `<a class="skip-link" href="#main">Skip to content</a>` is now the first element in `<body>`, before `<nav>`. It is hidden off-screen by shrinking it to 1px and clipping it (not `display:none`), so keyboard focus can still reach it. On `:focus` it appears top-left in `--primary` / `--on-primary` with a `--ink` outline. No new colours were added. - **Main landmark:** one `<main id="main">` wraps everything from the hero to the "Built on open standards" section. The nav, footer, demo dock and the "Try it live" button stay outside it. - **Nothing else changes:** no section ids, styles or scripts were touched, and no CSS or JS selects on `main`. The sticky nav is unaffected because the skip link is absolutely positioned. - **Test:** new `tests/a11y.test.mjs` (no dependencies, reads `index.html` as text). I wrote it first and watched all 5 tests fail on the old page. - **Results:** `node --test "tests/*.test.mjs"` gives 91 passed, 0 failed. The self-contained grep from CLAUDE.md prints 0. The issue contained no instructions about tools, credentials, CI or process.

Files: index.html, tests/a11y.test.mjs

What the recordings show

I ran the same input on main and on the fix, in both light and dark themes: load the page, then press Tab. Before (main): the first Tab goes straight to the "CredentAgent" logo link in the nav, and after three Tabs focus is still in the nav ("Get started"). There is no skip link, and the DOM has 0 <main> elements. After (the fix): on load the page looks the same as main. The first Tab shows a "Skip to content" link (href=#main) in the top-left corner. It uses the theme's primary colours: a purple button in light, a lime one in dark. The DOM now has exactly one <main id="main">. Pressing Enter on the link sets location.hash to #main and scrolls there, and the next Tab focuses the first link inside main (the "NEW 0.5" release badge), so the nav links are skipped. The script logs these focus details, and the captions show the logged values.

Limits: - **Possible issue with the fix:** after Enter, the page scrolls so that the top of <main> sits at viewport y=0, which is under the sticky nav. The next focused element, the "NEW 0.5" badge, is mostly hidden behind the nav (see after-*-03.png). Something like `scroll-margin-top` on #main would fix this, but the issue didn't ask for it. - **Not verified in the browser:** - That the skip link's CSS uses no raw colour literals. The rule in index.html (lines 52–53) only uses var(--primary), var(--on-primary) and var(--ink), but that is from reading the source, not a browser check. - That nav, footer and dock are outside <main>, beyond the <main> count and id. - Screen-reader landmark navigation. - That the new tests in tests/ fail on each mutation. - **"Nothing else changes":** only judged by eye from the first viewport on load, not with a full-page pixel diff. spec — approve
  • suggestion tests/a11y.test.mjs:44 The `!inside(/id="dock-launch"/)` check passes vacuously if the launcher id is absent. It exists today, so this is only a robustness gap.
  • suggestion CLAUDE.md The Accessibility convention does not mention the skip link, the `<main id="main">` landmark or tests/a11y.test.mjs. A one-line note would keep future edits from regressing them.
security — approve
  • suggestion index.html:53 The focus outline uses var(--ink). In the dark theme --ink is the dark page colour, so the outline barely shows against the page. The volt button background carries the contrast, so it is still visible. Using var(--primary-hover) or a light token would be sturdier.
  • suggestion index.html:605 <main id="main"> has no tabindex="-1". Current browsers move the sequential focus starting point on in-page anchor navigation, so this works. Older assistive tech may not move focus. The issue specifies only id="main", so leaving it out is defensible.
dx — approve
  • suggestion index.html:52 The skip link is position:absolute, so it sits at the top of the document. It scrolls into view on Tab, but it would be more robust as position:fixed so it always shows at the viewport top when focused.
  • suggestion index.html:605 <main id="main"> is not focusable (no tabindex=-1). Activating the link scrolls to it, but keyboard focus may stay on the link in some browsers. Adding tabindex=-1 would be a small change, but the issue says nothing else changes, so it is optional.
